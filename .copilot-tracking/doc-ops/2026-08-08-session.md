## Discovered Issues

### Pattern Compliance

### Accuracy Discrepancies

* The README describes the worker only as a read-only prototype, but the
  implementation claims triggers, starts and resumes runs, manages leases,
  checkpoints state, calls read tools, and marks triggers completed or failed.
* The normal run example omits required and important configuration, including
  `AGENT_SERVER_BASE_URL`, timing options, feature gates, Foundry settings,
  logging, and telemetry.
* `AGENT_PRINCIPAL_ID` is ambiguous. It is the pre-provisioned database agent
  principal UUID, not the Azure Container App managed identity object ID.
* Authentication docs omit the `DefaultAzureCredential` behavior, server token
  scope/audience requirements, and `agent.runtime` app-role contract.
* Static token wording is contradictory. Production static server tokens and
  static Foundry tokens are unsupported, while test-only static server tokens
  are allowed under `NODE_ENV=test`.
* The README omits control-plane polling, trigger claiming, active assignment
  checks, lease lifecycle, checkpoint recovery, and completion/failure
  reporting.
* The README omits the implemented read-only tool endpoints, UUID validation,
  redaction, and response size limits.
* The README omits gateway defaults and feature gates, including fake gateway
  default and disabled Foundry/structured proposal defaults.
* The README omits the `control_plane_access_verification` preflight check.
* The test command lacks setup steps for dev dependencies and does not mention
  Postgres integration tests gated by `AGENT_WORKER_POSTGRES_TEST_DSN`.

### Missing Documentation

* Add production prerequisites: server read route activation,
  `FEATURE_AGENT_READS_ENABLED`, Entra app-role assignment, app-only token
  validation, and restricted control-plane access.
* Add configuration tables for required runtime variables, optional operations
  variables, gateway and Foundry variables, and test-only variables.
* Add operations, recovery, read-tools, and observability sections.
* Add current MVP versus planned capabilities, including Foundry conversation,
  historical context synthesis, lifecycle states, structured proposals, and
  future expansion gates.
* Add explicit non-goals: no production static server tokens, no Entra Agent ID
  MVP dependency, no canonical database writes, no direct canvas mutation
  authority, no durable user memory, no default raw prompt/response retention,
  and no Agent Framework Harness.
